Tips & credentials

Accounts

Hardcoded, because a teaching API has to let the room in. Use ticks Authorization Basic and fills it in — the base64 happens in front of you.

  • viewer:viewerpass role viewer — opens /viewer
  • editor:editorpass role editor — opens /viewer and /editor
  • admin:adminpass role admin — opens all three
  • dataschool:dataschool role viewer — the one POST /echo greets by name

Roles rank rather than match, which is why admin reaches /viewer. A token that is valid but not senior enough gets 403, not 401 — and the difference is the whole reason those three endpoints exist.

Keys

A key says which program is calling. A token says which person. Confusing the two is how a long-lived credential ends up hardcoded in a phone app.

  • nutshell-demo-key this backend, as X-API-Key, on GET /app

OpenWeatherMap, for slide 16 — rides in the URL as appid, never in a header, which is why it lands in browser history and server logs

Endpoints

Click one to load it into the request. The host is kept as you have it, so a localhost session stays on localhost.

  • the plainest possible request — no credential
  • the only endpoint that reads a body — needs Basic
  • query parameters — drop ?kind= or ask for mineral to see a 422
  • a POST with no body — trades Basic for a token to paste into the Bearer row
  • roles, and 401 vs 403 — need Bearer
  • a key identifying an application — needs X-API-Key
  • three per twenty seconds, then 429 — send it four times

The API describes itself

Every endpoint above has a second address that explains it. Open it and you get a page listing all of them — what each one needs, what each one answers, and which ones want a credential. It is not a reference to read alongside the API: there is a Try it out button on each entry, and an Authorize button at the top to hand it a username and password first, so you can make every call on this page from that one instead.

What makes it worth trusting is that nobody wrote it. The server generates it from the same code that answers the requests, every time it starts — so it cannot describe an endpoint that no longer exists, or forget one that was added yesterday. That is the difference between documentation and a wiki. The description format is called OpenAPI; the page that draws it is Swagger UI. You will meet both again on somebody else's API.
